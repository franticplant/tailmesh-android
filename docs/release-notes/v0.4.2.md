Tailmesh 0.4.2 adds a WireGuard server on the phone, subnet routes per tailnet and direct tailnet connections over the USB tether or hotspot. It also shows how each tailnet peer is reached, brings back a tailnet whose node failed to start, and uses much less CPU while the app is closed.

Installs as an update over 0.4.x and 0.3.x, keeping your tailnets and settings. Most phones want the `arm64-v8a` APK; use `universal` if unsure.

## New: WireGuard listeners

**Settings → WireGuard listeners** runs a WireGuard server on the phone. Peers (a laptop, another phone) connect to it, and their traffic leaves through one upstream you pick. With `@auto` it is routed like the phone's own traffic: tailnet addresses go to their tailnet, then accepted subnet routes, then the default route. Adding a peer creates its key and address (default subnet `10.66.66.0/24`, the phone is `.1`) and gives you a wg-quick config to copy or share. The peer's private key is not stored on the phone. Each listener shows its peers' last handshake, source address and bytes, and the listeners come back on their own after a restart or an update.

By default the phone's own resolver answers every DNS query from a peer. Tailnet names resolve, and with a DoH resolver set (Settings → DNS) no plain DNS leaves the phone for a peer. Turn this off per listener to forward peers' DNS as before.

## New: subnet routes per tailnet

Each tailnet card in Multi-Tailnet has a **Use subnet routes** switch (off by default), like `tailscale up --accept-routes`. The tailnet's advertised routes then go to that tailnet, even inside a private range that "LAN stays direct" would keep out of the VPN. If two tailnets advertise the same prefix, the tailnet that was added first wins, and the card and Diagnostics show the conflict.

## New: direct tailnet connections over cable or hotspot

**Settings → Direct tailnet connections over cable or hotspot** (off by default, Multi-Tailnet only). Without it, a tailnet device on the phone's USB tether or hotspot is always reached through a DERP relay. With it on, the connection can go directly over the cable. The setting pauses itself on any network where it could send IPv6 over the wrong network, and resumes when that is no longer the case.

## Changes

- **Peer paths.** In Diagnostics, an expanded tailnet lists its online peers and how each is reached: direct, peer relay, DERP (with region) or idle. Before, the path showed "unknown" unless the tailnet had an exit node set.
- **Less work in the background.** The Multi-Tailnet state poll runs every second only while the app is open: every 15 s otherwise, and every 60 s with the screen off. Tailnet status polls run every 30 s while the app is closed. The once-a-second port-list poller is off, and WireGuard keepalives no longer fill the log. With no app screen open, CPU use dropped by about a third.
- **Steadier speed meter.** The status-bar speed is averaged over 3 seconds instead of 1, so a steady download no longer flickers between 0 and double its rate. The notification is updated only when its text changes.

## Fixes

- **A tailnet that fails to start is retried.** If a tailnet's node failed to start, for example right after a reboot or an update, the tailnet stayed STOPPED until Multi-Tailnet was restarted. It is now retried with backoff (5 s up to every 5 min) and shows as ERROR with the reason in the meantime. This is a likely cause of the "Tailnets STOPPED" reports after automatic restarts.

## Under the hood

- CI and the release workflow check every release APK for dev-only features (remote app updates, remote shell) and fail if any are present.
